# SberAzsMonitoring

Автономная микросервисная экосистема для непрерывного Time-Series мониторинга и уведомлений о динамике данных СберАЗС.
Сбор аналитики о наличии бензина на АЗС по регионам на данных sberazs.ru. Отправка уведомлений о наличии бензина в топики ntfy.
## 🧱 1. Архитектура системы и Стек технологий

Система построена на платформе **.NET 10.0** с разделением на независимые сервисы и слои по принципам Clean Architecture / DDD. Архитектура спроектирована под горизонтальное масштабирование.

* **API Gateway (`ApiGateway`)**: Единая точка входа для внешних запросов на базе *Yarp.ReverseProxy*.
* **Mvc**: Веб интерфейс с графическим представлением доступности АЗС.
* **Панель управления (`SberAzsMonitoring.Dashboard.Api`)**: REST API административной панели.
  * *Слой данных*: **PostgreSQL** (хранение конфигураций фирм-тенантов и их финансовых балансов через EF Core).
* **Слой фоновой обработки и шина данных**:
  * **Apache Kafka**: Распределенный брокер сообщений для обмена интеграционными событиями.
  * **ClickHouseWorker**: Вычитывает стрим из Kafka и агрегирует Time-Series срезы в СУБД **ClickHouse** для накопления истории и последующего анализа статистически значимой информации.
  * **NotificationWorker**: Консьюмер Kafka, обрабатывающий бизнес-логику и отправляющий сообщения на смартфоны через авторизованные топики локального сервера **ntfy**.
  * **Региональные воркеры (`WebApi`)**: Изолированные сервисы со встроенным фоновым планировщиком `FuelBackgroundScheduler`. Архитектурно система позволяет разворачивать **неограниченное количество сервисов WebApi** — по одному самостоятельному инстансу на каждый новый регион.

## 🎛 2. Управление системой (Административный интерфейс)

Полное управление экосистемой полностью вынесено на уровень Web API. Администратору доступны следующие возможности:
* **Создание фирм-тенантов**: Регистрация новых клиентов в системе.
* **Управление балансом фирм**: Инфраструктурно подготовленная база для монетизации (установка, списание и контроль лимитов).
* **Управление подписками фирм**: Привязка и удаление защищенных каналов уведомлений.

Весь интерфейс администрирования снабжен интерактивной документацией и REST-клиентом на базе **Scalar UI** (доступен в рантайме по адресу `http://localhost:5003/scalar`).
Открыть веб интерфейс: `http://localhost:7300`


## 🔐 3. Монетизация и Безопасность пушей

* **Монетизация**: В СУБД PostgreSQL заложена логика ведения баланса фирм. Система готова к коммерческой тарификации каждогодоставленного пуш-уведомления.
* **Безопасность ntfy**: Вся доставка пушей переведена на собственный локальный сервер ntfy. Вместо публичных каналов реализована **строгая авторизованная подписка на топики**. Доступ к получению уведомлений имеют только аутентифицированные смартфоны клиентов.

## 🛠 4. Как запустить проект в Docker

### Предварительные требования
* Установленный Docker Desktop / Docker Compose
* .NET 10.0 SDK (для локальной разработки)

### Быстрый старт
1. Склонируйте репозиторий.
2. Откройте терминал в корневой папке и запустите всю инфраструктуру:
   ```bash
   docker-compose up -d --build
   ```
